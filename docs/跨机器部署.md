## 0. 那一屏报错，到底是怎么来的

你贴的：

```
'voice' is not recognized as an internal or external command,
operable program or batch file.
'+' is not recognized as an internal or external command,
operable program or batch file.
[错误] 找不到虚拟环境：C:\Users\Administrator\PycharmProjects\mcszr\.venv\Scripts\python.exe
Press any key to continue . . .
```

三行三个原因，**互相无关**：

| 输出 | 真实原因 |
|---|---|
| `'voice' is not recognized...` | `.bat` 的行尾被存成了 **LF**（或中文出现在 `chcp 65001` 之前）。cmd 是**边读边按当前代码页解析**的，UTF-8 的汉字被切成残字节，碎片就被当成命令去执行 —— `voice` 正是 `E:\conda3\envs\voice\python.exe` 那一行的碎片，跟"语音"本身没关系 |
| `'+' is not recognized...` | 同一个原因，碎片来自带 `+` 的路径/文字 |
| `[错误] 找不到虚拟环境：...\PycharmProjects\mcszr\.venv\...` | 老脚本用 `set PY=%ROOT%.venv\Scripts\python.exe`，`%ROOT%` 取的是**脚本自己所在目录**。脚本被拷到 `...\PycharmProjects\mcszr\` 这个老目录、而那里没有 `.venv`（`.venv/` 在 `.gitignore` 里，本来就不会跟包走），于是脚本按设计 `exit /b 1` |
| `Press any key to continue . . .` | 就是脚本里的 `pause`，不是错误 |

**实测复现**（在本机跑出来的，不是推测）：把改造前的
`启动数字人_语音版.bat` 写成 LF 行尾再执行，cmd 立刻吐出一串
`'<中文碎片>' is not recognized as an internal or external command`。
改造前的原文件是 **UTF-8 + CRLF**（前 40 字节
`40 65 63 68 6F 20 6F 66 66 0D 0A 63 68 63 70 ...`），所以它在本机是好的；
坏就坏在"换个编辑器/换台机器另存了一次"。

## 2. 新电脑：三步

### 第一步：装 Python 3.10
官网安装包，勾 **Add python.exe to PATH**。（3.9~3.12 都能用，3.10 是官方口径。）

### 第二步：双击 `一键部署_新电脑.bat`

它做四件事：

1. 检查基础解释器（3.9~3.12；如果你机器上只有 3.13/3.14，会自己挑一个更稳的）
2. 建 `.venv`（已存在就跳过）
3. `pip install -r requirements.txt`（只有 `edge-tts` 一个第三方包）
4. 探测语音识别/GPU/产线库/数据集/浏览器，**只填空项**写回 `config\paths.ini`，
   顺手把 `C:\dh_root` / `C:\dh_prod` / `C:\dh_ds` 三条软链建好，然后打体检表

先看计划不动手：`一键部署_新电脑.bat --check`；
只建 venv 不装包：`--no-install`；离线：`--offline`（见第 5 节）。

### 第三步：双击 `启动数字人_语音版.bat`

| 参数 | 作用 |
|---|---|
| `--check` | 只体检不起服务；有 FAIL 退出码 1（自动化能用） |
| `--no-window` | 起服务不开浏览器窗口 |
| `--no-asr` | 不拉语音识别，本轮只能打字 |
| `--no-pause` | 结束不等按键 |

## 3. 体检表怎么读

`启动数字人_语音版.bat --check` 的输出分三级：

- **OK**：就绪
- **WARN**：缺了它功能降级，但能跑（下表）
- **FAIL**：起不来 / 起来了也是哑的，必须先修

| 项 | 缺了会怎样 | 能不能带病跑 |
|---|---|---|
| 主解释器 | 什么都起不来 | 不能（FAIL） |
| 项目 `.venv` | 还没有虚拟环境 | 能，但下一步会 FAIL |
| `edge-tts` | 主服务能起，**没有声音** | 启动脚本会拒绝启动（FAIL），跑一次部署就好 |
| 语音识别环境（funasr） | 只能打字，不能说话 | 能（WARN） |
| GPU 环境（torch+ultralytics） | ⑤"调度 GPU"那块失效 | 能（WARN） |
| 产线库 `wood_inspect.db` | 查数类回答会说"库不存在" | 能（WARN） |
| 数据集 | 训练类作业报"数据集不存在" | 能（WARN） |
| 浏览器 Chrome/Edge | 用系统默认浏览器开地址 | 能（WARN） |
| ASCII 软链 `C:\dh_root` | 训练类作业会因为中文路径失败 | 能（WARN）：`一键部署` / `启动` / `dh_env.py --check` 都会自动建（junction，不需要管理员） |

## 4. 路径优先级

任何一项都可以用**环境变量**覆盖 ini（适合多套环境共用一份代码）：

| ini 键 | 环境变量 | 含义 |
|---|---|---|
| `PYTHON` | `DH_PY` | 主服务解释器 |
| `ASR_PYTHON` | `DH_ASR_PY` | 装了 funasr 的解释器 |
| `GPU_PYTHON` | `DH_GPU_PY` | 装了 torch( CUDA )+ultralytics 的解释器 |
| `PROD_ROOT` | `DH_PROD` | 产线工程目录（指向 `new mcjc` 本身） |
| `DATASET_ROOT` | `DH_DS` | 缺陷数据集根（含 `images/train`） |
| `BROWSER` | `DH_BROWSER` | Chrome/Edge 的 exe |
| `PORT` / `ASR_PORT` | —— | 8772 / 8773 |

顺序：**环境变量 > `config\paths.ini` > 自动探测 > 历史默认值**。
值留空就是"自动探测"，探测逻辑全在 `_tools\dh_env.py`，想看它探到了什么：

```bat
.venv\Scripts\python.exe _tools\dh_env.py --json
```

### 语音识别环境（要说话才需要）

```bat
py -3.11 -m venv D:\envs\voice
D:\envs\voice\Scripts\python.exe -m pip install -r requirements-asr.txt
```

然后把 `D:\envs\voice\Scripts\python.exe` 写进 `config\paths.ini` 的 `ASR_PYTHON=`。
（不写也行：探测会去找 conda/venv 里带 funasr 的环境，`~/.conda/environments.txt` 会被读。）

### GPU 环境（要用 ⑤ 那块才需要）

```bat
conda create -n gpu python=3.10 -y
conda activate gpu
pip install torch --index-url https://download.pytorch.org/whl/cu124
pip install ultralytics
```

同样写进 `GPU_PYTHON=` 或设 `DH_GPU_PY`。

## 6. 改 `.bat` 的三条红线

1. **行尾必须 CRLF**。LF 的 `.bat` 在 cmd 里会被拆成残缺命令，报
   `'xxx' is not recognized`，`xxx` 往往是中文碎片。
2. **不能有 BOM**。BOM 会粘在第一行 `@echo off` 前面，第一行直接失效。
3. **文件是 UTF-8 时，`chcp 65001` 必须在第一处中文之前**。cmd 边读边解析，
   先切代码页再读中文。

改完跑一遍：

```bat
.venv\Scripts\python.exe _tools\bat_lint.py --check     :: 只检查
.venv\Scripts\python.exe _tools\bat_lint.py --fix       :: 就地修成 CRLF + 去 BOM
```

> 别用记事本/某些编辑器"另存为 UTF-8"直接改 `.bat`——这就是本次事故的起点。

## 7. 错误对照表

| 现象 | 真实原因 | 修 |
|---|---|---|
| `'xxx' is not recognized as an internal or external command`，xxx 是中文碎片 | bat 行尾 LF / 有 BOM / `chcp` 在中文之后 | `_tools\bat_lint.py --fix` |
| `[错误] 找不到虚拟环境：<某个老路径>\.venv\Scripts\python.exe` | 老脚本写死 `.venv`，而新机器没有 | 双击 `一键部署_新电脑.bat` |
| `[FAIL] edge-tts 语音合成 未装` | `.venv` 没建或没装依赖 | 同上 |
| `[WARN] 语音识别解释器` | 没有带 funasr 的环境 | 装一个并写 `ASR_PYTHON=`，否则只能打字 |
| `[WARN] ASCII 软链 … dh_root:missing` | 还没建（`--no-fix` 只读模式，或不是从部署/启动脚本进来的） | `python _tools\dh_env.py --fix`，或直接 `--check`（默认会自愈） |
| `[WARN] ASCII 软链 … dh_root:stale` | `C:\dh_root` 指的是别的项目（以前 clone 到别处的残留） | `python _tools\dh_env.py --fix`：只删链接本身再重指，不会动目录里的东西 |
| `[WARN] 产线库 … PROD_ROOT=<path> 在这台机器上不存在` | `config\paths.ini` 里留着别的机器的绝对路径 | 改成这台机器的 `new mcjc`，或把那行清空交给自动探测 |
| 主服务起来了但页面空白 | 8770/8999/8790 那三块外部系统没开 | 见 `板材数字人_四屏舞台_20261113\05_服务\启动四屏.bat --check` |
| `[spawn] xxx: 起来就退了` | 解释器不对/端口被占/依赖缺失 | 看 `logs\<名字>.log` 尾部（脚本会自动打印最后 12 行） |

日志位置：`logs\server.log`、`logs\asr.log`（`_tools\dh_spawn.py` 写入）。

### 2026-11-15 补充：ASCII 软链改成「自愈」，不再是一个 FAIL
新机器 clone 下来直接跑体检，会看到：

```
[FAIL] ASCII 软链  dh_root:missing dh_prod:no-target dh_ds:no-target
       └ 启动脚本会自动 mklink /J 建 dh_root；dh_prod/dh_ds 只在目标存在时建
```

这条其实是**误报级别用错了**：`dh_root` 缺了不影响启动（启动脚本第一步就建），
却按 FAIL 算，把「结论：不能启动」也带偏了。现在：

| 变化 | 行为 |
|---|---|
| `dh_env.py --check` | 默认顺手把缺的软链建好、指错方向的改回来（junction 不需要管理员），表里直接 OK |
| `dh_env.py --check --no-fix` | 纯只读，软链不 OK 时标 **WARN**（不再是 FAIL），结论仍是「可以启动」 |
| `dh_env.py --fix` | 单独修软链；`stale` 只删链接本身再重指，目录内容不动（真实目录非空时 `rmdir` 会失败，因此不会误删） |
| `dh_deploy.py` / `一键部署_新电脑.bat` | 写回 ini 之后顺手建软链，打印 `[ok] ASCII 软链 …` |
| 产线库/数据集 WARN | 若 `paths.ini` 里写的是**别的机器**的路径，提示会直接把那个值打出来，说明「本机不存在，改它或清空」 |

实测（本机，2026-11-15）：删掉 `C:\dh_root` 后 `--check --no-fix` 报
`dh_root:missing` + WARN、退出码 0；直接 `--check` 自动重建并回到
`dh_root:ok dh_prod:ok dh_ds:ok`；把 `C:\dh_root` 故意指到别的项目后报 `stale`，
`--fix` 改回本项目。

## 9. 只部署那几块屏（另一台电脑，不带产线）

场景：展厅 / 答辩机只放「小星 + 五块屏」，产线系统仍然留在产线机上。
以前这套屏是假设"本机就是产线机"的（iframe 写死 `127.0.0.1:8770` / `:8999`，
数据直接从本机 `wood_inspect.db` 算），换台机就是白屏 + 8790 报 500。现在改成：

| 块 | 数据/画面来源 | 这台机器没有产线时 |
|---|---|---|
| ① 检测系统 | `8790 /api/win/desktop.jpg`（GDI 抓 `run.py` 窗口，需要 **Pillow**） | 显示「检测系统未连接」 |
| ② 大屏可视化 | iframe → `SCREEN_URL`（默认 127.0.0.1:8770） | 显示「大屏未连接」 |
| ③ 六专家复核 | iframe → `AGENT_URL`（默认 127.0.0.1:8999） | 显示「对话中枢未连接」 |
| ④ 自学习闭环 | `/api/stage`（读产线库 `ai_learning_*`） | 照常渲染，数字全 0，并打一行说明 |
| ⑤ 模型性能·GPU | `/api/ops`（8772 本机采样） | 照常（GPU 0%、作业空闲） |

### 这台电脑上怎么起

```bat
一键部署_新电脑.bat                        :: .venv + edge-tts + Pillow
启动数字人_语音版.bat                      :: 8772 主服务，/xx/xiaoxing5.html 由它托管
板材数字人_四屏舞台_20261113\05_服务\启动四屏.bat   :: 8790 舞台；没有产线会自动跳过 8770/8999/run.py
:: 浏览器打开 http://127.0.0.1:8772/xx/xiaoxing5.html
```

### 把屏接到产线机（远端模式）

在这台机的 `config\paths.ini` 里加两行（值留空 = 本机）：

```ini
SCREEN_URL=http://<产线机IP>:8770
AGENT_URL=http://<产线机IP>:8999
WIN_TITLE=                      ; 只有那台 run.py 的窗口标题不一样才需要填
```

产线机那边三个服务都得监听 `0.0.0.0`（默认是 `127.0.0.1`，只有自己机器能连）：

```bat
python screen_service.py --host 0.0.0.0 --port 8770
python angent\agent_service.py --host 0.0.0.0 --port 8999
```

> ① 屏抓的是**本机窗口**，远端产线机的桌面窗口抓不过来 —— 那台机没跑 `run.py`
> 就一直显示「未连接」。这是设计取舍（真窗口 vs 假仪表盘），不是 bug。

### 自检

```bat
python 板材数字人_四屏舞台_20261113\05_服务\stage_server.py --check   :: 有产线 0、没产线 1
板材数字人_四屏舞台_20261113\05_服务\启动四屏.bat --check            :: 列出解释器/产线/舞台包/远端地址
```

### 三个坑（都已处理）

1. **Pillow 没进依赖**：`wincap.py` 用 Pillow 编 JPEG，旧 `requirements.txt` 只有 `edge-tts`，
   拿 `.venv` 起舞台时 ① 屏永远「未连接」。现在 `requirements.txt` 里加了 `Pillow>=10.0`。
2. **没产线时 8790 直接 500**：`build_snapshot.py` 原来把 `new mcjc` 路径写死。现在按
   `DH_PROD` > `paths.ini` 的 `PROD_ROOT` > `dh_env.py` 自动探测；都没有就给**空快照**
   （`deployed:false` + `note`），保证 `/api/stage` 仍 200。`build_snapshot.py` 在没产线的机器上
   默认**不写** `snapshot.json`（免得把 0 覆盖进仓库里的模板），要写加 `--force`。
3. **iframe 地址写死**：现在由 `/api/stage` 的 `urls` 下发，页面按 `live` 决定"嵌进去"还是"显示占位"；
   8772 也新增了 `/api/win/*` 转发，页面用同源相对路径就够了。
