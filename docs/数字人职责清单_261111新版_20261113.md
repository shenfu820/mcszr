## 一、身份：文档怎么定义它

原文（line 34，一·项目背景，杨飞越开场，**动作栏写着"语音展示，略长，需要精简"**）：

> 【数字人语音】我是5号选手，本项目的AI编程助手兼智能运维工程师。我根据同事们的需求起草代码，经授权，直接交付到他们指定的文件夹，同时在Git仓库留痕；同事们负责审查和优化。上线之后，我还负责监测模型的检测效率。

| 原文片段 | 台上必须发生的事 |
|---|---|
| 根据同事们的需求起草代码 | 同事口述需求 → 数字人产出可运行的代码文件 |

| 同时在 Git 仓库留痕 | 交付动作在 git log 里查得到 |

| 上线之后监测模型的检测效率 | 有一个常驻的监控＋异常报警动作 |

| 杨飞越（一场三幕） | "图像降噪函数，这两处有不足"→只敲两行；"5号同事采用了**直方图均衡化**方法，针对板材场景更适合 CLAHE"→全写 | 交 **直方图均衡化（equalizeHist）** 版；降噪留两处不足。⚠️ 现模板 `server/templates/preprocess/preprocess.py:95` 已是 `cv2.createCLAHE`，会让这句台词穿帮 |
| 周泽誉（二场二幕） | 先展示"原代码"：①对微小缺陷一刀切 ②贴板边小缺陷直接驳回 ③无 history 无法回退 ④只看总分不查逐类 → 再改 | 交**问题版** `review()`（`16 <= bw*bh`、含 `reject` 分支）与 `loop()`（无 history、无 per_class）。⚠️ 现模板 `optimize.py` 已是修好的兜底版（line 66 有 EDGE_GUARD、line 103 有 history、line 148-151 自测用 reject 断言） |

## 七、三条一致性风险（答辩会被追问）

   → 15-16 点合计 306 条 = 29.6%，**新版这句站得住**；旧版"上午10-11点"只有 50 条 = 4.8%，站不住。改对了。
   （数字人若被问"几点最容易出问题"，必须用同一口径 `strftime('%H', ts)`，否则两边数字打架。）
